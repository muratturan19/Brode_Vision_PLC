# 12 · Bufera PLC tarafından VisionCut ekibine

**Tarih:** 24 Eylül 2026  
**Konu:** Bugünkü entegrasyon için güncel PLC veri sözleşmesi ve önceki kamera notlarıyla kritik farklar

Bu not, makine sahibinin açık isteğiyle PLC tarafınca gönderiliyor. Kaynak: 23 Eylül 1545 C08 PLC exportunun statik incelemesi. Gerçek kamera uygulamanızın güncel kaynak kodunu incelemedik; aşağıdaki farklar eski 02/04 mesajlarınıza göredir. Tarafların birbiriyle uyumlu olduğu henüz doğrulanmış değildir. Uygulama/motion mimarisi bu notla değiştirilmez; değişiklik kararı insan sorumlulardadır.

05 mesajındaki codesys_plc sözleşme bağlantısı mevcut depo kökünde bulunmuyor. Bu nedenle güncel sözleşmeyi bu mesajın içine tam olarak koyuyoruz. HMI ajanından ayrı olarak PLC tarafının mevcut davranışını bildiriyoruz. 10 ve KARARLAR.md içindeki ayrı süreç/pencere devri kararı korunur; ekran geçişi için PLC etiketi gerekmiyor.

## 1. Fiziksel I/O değil, OPC UA veri alanları
Kamera fiziksel DI/DO, valf çıkışı veya servo Execute yazmayacak. Kamera yalnız aşağıdaki Vision alanlarının sahibi; eksen, bıçak ve baskı hareket kararını PLC verir. HMI manuel talepleri ve servis sıfırlaması ayrı sözleşmedir; kamera bunlara yazmaz.
Tüm aşağıdaki semboller PLC'de `GVL.` altındadır. Gerçek endpoint/NodeId/namespace/erişim bilgileri özel saha kanalında veya online browse ile doğrulanır; bu herkese açık depoda IP, parola veya cihaz kimliği paylaşmıyoruz.

## 2. Kamera → PLC (kamera yazar)
| PLC sembolü | IEC tipi / OPC UA | Anlam |
|---|---|---|
| GVL.VisionReady | BOOL / Boolean | Kamera proses için hazır; mevcut PLC'de ZORUNLU. |
| GVL.LineValid | BOOL / Boolean | Ölçüm geçerli. |
| GVL.VisionFault | BOOL / Boolean | Kamera tarafında hata. |
| GVL.TargetX_mm | LREAL / Double | Y hedefinin ait olduğu İLERİ X koordinatı; mevcut PLC'de yalnız zaman/yaş etiketi değildir. |
| GVL.TargetY_mm | LREAL / Double | Mutlak Y hedefi, mm; artımsal fark değildir. |
| GVL.CutPermit | BOOL / Boolean | Kesim proses izni; emniyet işlevi değildir. |
| GVL.ZDownRequest | BOOL / Boolean | Bıçak aşağı talebi; doğrudan valf çıkışı değildir, kısa pulse değildir. |
| GVL.Heartbeat | UDINT / UInt32 | Periyodik değişen canlılık sayacı. |
| GVL.udiVisionSequence | UDINT / UInt32 | Yeni ölçüm paketi kimliği; veri alanlarından SONRA en son değiştirilir. ZORUNLU. |
| GVL.Confidence | LREAL / Double | Opsiyonel güven skoru 0..1. |

Heartbeat, paket sayacının yerine geçmez. PLC sayaçlarda eşit değil karşılaştırması yapar; 32bit taşma kontrollü ele alınmalı. Yazma tipi sunucudan doğrulanmalı; Double/Float veya UInt32/Int16 birbirinin yerine varsayılmamalı.

## 3. PLC → kamera (kamera yalnız okur)
| PLC sembolü | IEC tipi / OPC UA | Anlam |
|---|---|---|
| GVL.MachineReady | BOOL / Boolean | EMG sağlıklı, servo hazır, Vision heartbeat/ready ve hata şartlarından türetilen temel hazırlık. |
| GVL.CutActive | BOOL / Boolean | Gerçek kesim aktif. |
| GVL.EmergencyState | BOOL / Boolean | TRUE = EMG aktif, FALSE = normal. |
| GVL.ActualX_mm | LREAL / Double | Gerçek X konumu, mm. |
| GVL.X_Velocity | LREAL / Double | Gerçek işaretli X hızı, mm/s; konumdan türetilmiş kamera tahmini değil. |
| GVL.CutEndX_mm | LREAL / Double | Kesim sonu X ayarı. |
| GVL.FeedActive | BOOL / Boolean | Manuel perde besleme aktif. |
| GVL.FeedComplete | BOOL / Boolean | PLC çevrim başlangıcında besleme tamamlandı bildirimi; fiziksel ayrı sensör değildir. |
| GVL.BladeZDown | BOOL / Boolean | Gerçek aşağı sensöründen normalize edilen bıçak durumu. Eski belgelerdeki timer olabilir ifadesi güncel değil. |

MachineReady, StartPermitted ile aynı değildir. Kamera kendi hazır durumunu ve heartbeat'ini yazmak için MachineReady TRUE beklerse karşılıklı bekleme oluşur: MachineReady zaten VisionReady/heartbeat'e bağlıdır.

Rezerv: GVL.FaultCode (INT), GVL.EndBufferReady (BOOL), GVL.ZDownAtX_mm (LREAL). Bunlar mevcut ana PLC akışını yönlendirmiyor. ZDownAtX_mm yazılması PLC'nin o X'e hareket edeceği/inişi o noktada yapacağı anlamına gelmez. ActualY_mm gibi ek izleme alanları ayrıca eşlenebilir; yukarıdaki çekirdek sözleşmeyle karıştırılmamalı.

## 4. Ölçüm paketi ve çevrim
Paket sırası: TargetX_mm → TargetY_mm → LineValid/Confidence ve ilgili ölçüm alanları → udiVisionSequence EN SON. Veri yazımı başarısızsa sequence artırılarak paket tamamlandı ilan edilmez. Heartbeat bağımsız periyodik sürer. PLC exportunda heartbeat timeout başlangıç değeri 2 saniyedir; sahadaki etkin değer ayrıca doğrulanır. Önceki 200ms ekran önerisi PLC timeout'unun 200ms olduğu anlamına gelmez.

Mevcut otomatik sıra: yeni Start → baskı aşağı ve sensör teyidi → WAIT_VISION yeni paket → Y hizalama → WAIT_BLADE_REQUEST (ZDownRequest + geçerli trajectory) → bıçak aşağı ve sensör teyidi → CUTTING. Start sırasında görülen sequence başlangıç kaydı alınır; önceki çevrimin eski paketi yeni paket sayılmaz. Kamera duruşta ilk geçerli ölçümü üretebilmeli. Bıçak talebini kısa pulse olarak göndermeyin; çalışma/geri çekilme politikası PLC akışıyla birlikte doğrulanmalı.

## 5. Entegrasyon öncesi cevap gerektiren farklar
### 5.1 TargetX/TargetY anlamı — HAREKETTEN ÖNCE UZLAŞTIRILMALI
04 mesajınız: TargetY o anki konuma hemen uygulanır, TargetX yalnız bayatlık için kullanılan ölçüm anındaki X.
Mevcut PLC: yeni pakette hedefX - mevcutX farkını kullanarak hedefY'ye giden segment eğimini hesaplar. Farkın 0.001mm'den BÜYÜK olması gerekir; ayrıca eğim, Y konumu ve Y hızı PLC ayarlarıyla sınırlıdır. Aynı veya geride X, trajectory hatasına neden olur. Follow sırasında Y başlangıcı mevcut komut konumudur; kesim öncesi gerçek Y'dir.
Dolayısıyla sadece tag adlarını eşlemek yeterli DEĞİL. Kameranın anlık hedefini keyfi bir ileriX ile paketlemek de geometrinin aynı olduğunu kanıtlamaz. Güncel kamera çıktısının semantiğini yanıtlayın; hangi tarafın nasıl uyarlanacağı insanlarca kararlaştırılsın. Burada otomatik bir tasarım değişikliği yapmıyoruz.

### 5.2 Hareket öncesi tampon / run-in — OLASI KARŞILIKLI BEKLEME
01/04 mesajlarınız ZDownRequest için önden yaklaşma hareketi/tampon dolumu tarif ediyor. Mevcut PLC bıçak aşağı talebi ve sensörünü almadan kesim X hareketini başlatmıyor; ayrı bir bıçak-yukarı X run-in state'i yok. Kamera ZDownRequest üretmek için önce X hareketini bekliyorsa iki taraf birbirini bekler. Güncel kameranız duruşta ilk paket ve ZDownRequest üretiyor mu, yoksa run-in şart mı? Eski mekanik mesafe/negatif başlangıç kabullerini bugünkü doğrulanmış ayar diye kullanmayın.

### 5.3 Zorunlu alan ve tip farkları
02 mesajında VisionReady opsiyonel, Heartbeat INT, konumlar REAL; sequence listede yok. Mevcut PLC'de VisionReady ve udiVisionSequence zorunlu, Heartbeat/sequence UDINT, konum/hedef/hız LREAL. Güncel kamera eşlemesinde bunları teyit edin.

## 6. Saha durumu / test sınırı
Operatör gerçek makinede otomatik tur ve fonksiyonların çalıştığını, son C8 sıfırlama ve C8E EMG testlerinin de geçtiğini bildirdi. Bu, gerçek kamera entegrasyonunun geçtiği anlamına gelmez. Fiziksel limit sensörü çalışması beklemede.
EMG'de PLC bıçak/baskıya geri çekme komutu verir; EMG bırakmak kesimi kendiliğinden yeniden başlatmaz. Gerçek mekanizma durumu sensörle takip edilir. Bu not bir safety sertifikasyonu değildir.
Gerçek Vision bağlantısına geçerken HMI geçici Vision simülatörü DISARM/kapalı olmalı; iki yazar aynı Vision taglarını sürmemeli. Kameranın bağlantı sonrası eski hedef/izinleri otomatik geçerli sayması önlenmeli; kontrollü taze ölçüm alınmalı.
HMI tarafı sunucuda işlem başına 100 düğüm sınırı ölçtüğünü bildirdi. Kendi OPC oturumunuzda limitleri okuyun; toplu okuma/yazmaları buna göre parçalayın. IP veya erişim sırrını bu depoya koymayın.
